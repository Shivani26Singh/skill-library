Skills turn your QA process into something versioned and shareable, instead of re-explained from memory each session — same testers, one shared standard.

The suite

Skills are independent — jump in at any phase. When an earlier phase's output exists, the next one reuses it instead of starting over.

What is a skill

Not a prompt. A file with four parts.

Base models are generalists. If you've explained the same procedure to your assistant three times this week, you've found a skill — one file it loads on demand, instead of a system prompt you keep re-pasting.

01

Header

Name, description, version.

02

Workflow

The exact steps the assistant follows, in order.

03

Output

The sections its answer must contain.

04

Guardrails

What it must never do.

pw-flaky-debugger/SKILL.md
--- name: pw-flaky-debugger description: >- Diagnoses a flaky Playwright test by collecting evidence, classifying the root cause (product / test / env / data), and proposing the smallest fix. license: MIT metadata: author: Shivani Singh pack: playwright version: 1.0.0 --- # never fixes flakiness with a longer wait — # it hunts the race, then hands you a diff

Consistency

Same request, same structured sections and terminology, regardless of who asked or which assistant runs it.

Traceability

Every finding traces to a stated requirement or piece of evidence — nothing is invented to fill a gap.

Human-in-the-loop

Every skill ends in a mandatory review gate — the assistant proposes, a person confirms before anything ships.

Independent & composable

Jump in at any phase. Upstream output is reused when it exists, but reuse is optional, never required.

Honest confidence

Every skill states High / Medium / Low confidence tied to evidence completeness — never to how polished it reads.

Faster cycles

A ticket ID becomes a review-ready draft — readiness score, test plan, scenarios, bug report — in minutes.

Running a skill

One folder. Support varies by tool.

An Agent Skill is a folder containing SKILL.md — YAML frontmatter plus Markdown instructions — optionally alongside references/, scripts/, or other supporting files the workflow opens only when a step needs them. That structure is the same everywhere. How a tool finds and runs it is not.

the folder + filename convention is universal
  • SKILL.md — required workflow file.
  • references/ — optional supporting knowledge.
  • scripts/ — optional executable tools.
  • Tool location — varies by assistant, see below.
